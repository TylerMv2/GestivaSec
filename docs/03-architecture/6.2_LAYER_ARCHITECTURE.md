# 6.2 LAYER ARCHITECTURE — GESTIVA SECURITY (GESTIVASEC V1)

---

## 1. Resumen Ejecutivo
El artefacto **SA-0003 Layer Architecture Specification** define la **Estructura de Capas Lógicas de Software** y las **Reglas Inviolables de Dependencia entre Capas** para **Gestiva Security (GestivaSec V1)**, fundamentadas en el patrón de Arquitectura Hexagonal y Monolito Modular aceptado en [`ADR-0015`](file:///home/sh4d0w/Projects/gestiva_observability/docs/adr/0015-adoption-of-hexagonal-ports-and-adapters-architecture.md).

Este artefacto **no define componentes, clases, adaptadores ni infraestructuras específicas**, acotándose estrictamente a delimitar las responsabilidades de cada capa y el flujo normativo de dependencias.

## 3. Responsabilidades por Capa de Software

### 3.1 Capa 1: Presentation Layer (Entrada / Adaptadores Primarios)
- **Propósito**: Recibir peticiones externas, adaptar formatos de entrada y enforzar la autenticación del contexto organizativo (`BR-0004`).
- **Responsabilidades**:
  - Validar el formato de entrada de datos externos.
  - Verificar la presencia y validez del contexto de Organización (`AP-0002`).
  - Traducir solicitudes externas hacia la Capa de Aplicación.
- **Regla de Dependencia**: Puede depender únicamente de la Capa de Aplicación (`Application Layer`). Jamás accede directamente a la Capa de Infraestructura.

### 3.2 Capa 2: Application Layer (Aplicación & Orquestación)
- **Propósito**: Coordinar los flujos de casos de uso y gestionar la ejecución de operaciones de aplicación.
- **Responsabilidades**:
  - Orquestar la secuencia de ejecución de los casos de uso.
  - Consultar los servicios de dominio.
  - Despachar eventos del dominio hacia los escuchas interesados (`ADR-0016`).
- **Regla de Dependencia**: Depende exclusivamente de la Capa de Dominio (`Domain Layer`).

### 3.3 Capa 3: Domain Layer (Dominio Puro - Clean Core)
- **Propósito**: Encapsular la lógica pura del negocio, las entidades, agregados, objetos de valor, máquinas de estado y reglas del negocio (`BR-0001` a `BR-0005`).
- **Responsabilidades**:
  - Enforzar las invariantes innegociables del negocio.
  - Definir las Raíces de Agregado y Objetos de Valor inmutables.
  - Definir las interfaces puras (Puertos) requeridas para la comunicación externa.
- **Regla de Dependencia**: **DEPENDENCIA CERO**. No depende de ninguna otra capa del software (`AP-0001`). No importa bibliotecas de infraestructura ni frameworks.

### 3.4 Capa 4: Infrastructure Layer (Infraestructura / Adaptadores Secundarios)
- **Propósito**: Proveer las implementaciones técnicas de los puertos definidos por la Capa de Dominio y la Capa de Aplicación.
- **Responsabilidades**:
  - Implementar las abstracciones de persitencia, notificaciones o integraciones.
  - Adaptar datos técnicos hacia las estructuras puras del dominio.
- **Regla de Dependencia**: Aplica el **Principio de Inversión de Dependencias (DIP)**. Depende de las interfaces expuestas por el Dominio y la Aplicación.
